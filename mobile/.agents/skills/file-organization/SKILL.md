# File Organization

<!-- TEMPLATE: the tables are the default layout for an Expo Router app and a separate backend. Adjust them to the project once, name real examples from the codebase as it grows, then delete this comment. -->

Use this skill before creating, moving, renaming or reviewing files. Follow the layout below; keep an existing local convention when a scoped change does not need a rename, and never rename files only for consistency.

## Where code goes

### App (`<mobile/ or root>`)

| Area | Path | What goes here |
| --- | --- | --- |
| Routes | `src/app/**` | Expo Router files only: `_layout.tsx`, `index.tsx`, `[id].tsx`, `(group)/`, `+not-found.tsx`. A route stays thin: it reads and validates its params, calls the data-access hooks and renders a component from `src/components`. **Every file here becomes a route**: components, hooks and helpers live elsewhere. |
| Root layout | `src/app/_layout.tsx` | The provider tree (query client, safe area, theme, state), font loading and the splash screen. Add a provider here, never in a screen. |
| Screen and feature components | `src/components/<feature>/` | One folder per feature or screen, holding its components and an `index.ts` barrel. |
| Reusable UI | `src/ui/<component>/` | Presentational building blocks any feature may use (`Button`, `TextField`, `Screen`, `ListItem`), each with an `index.ts`, re-exported from `src/ui/index.ts`. |
| API access | `src/data-access/<operation>/` | One folder per read or write (`fetchOrders/`): `<operation>.ts` (calls `apiClient`, parses with the schema), `validators.ts` (Zod schemas and inferred types), `use<Operation>.ts` (the TanStack Query hook), `index.ts`. The shared client is `src/data-access/apiClient.ts`; query keys live in `src/data-access/queryKeys.ts`. |
| Global client state | `src/state/<name>/` | App-wide contexts with pure reducers, or stores, with their types and an `index.ts`. |
| Device storage | `src/storage/` | Typed wrappers per stored key: schema, version, migration, and the secure-store wrapper for credentials. Nothing else reads MMKV, AsyncStorage, SQLite or SecureStore directly. |
| Hooks | `src/hooks/` | App-wide hooks, one flat file each (`useAppState.ts`). A hook used by one component stays beside it. |
| Notifications | `src/notifications/` | Push registration, payload schemas and the mapping from payload to route. |
| Analytics | `src/analytics/` | Tracking setup and event helpers with their types. |
| Theme | `src/theme/` | Color tokens for light and dark, spacing, radii, typography, and the hook that returns the current theme. |
| Shared helpers and types | `src/shared/` | Domain-free helpers (`formatPrice.ts`) and types several features use (`types.ts`). One file per helper, exported from `src/shared/index.ts`. |
| Assets | `assets/` | App icon, splash, fonts and images bundled with the app. |
| App configuration | `app.config.ts`, `eas.json` | Name, identifiers, scheme, permissions, plugins, build profiles. Values that differ per environment come from environment variables. |
| Config plugins | `plugins/` | Project config plugins for native changes no library plugin covers. |
| Native projects | `ios/`, `android/` | Generated by `npx expo prebuild`; not committed, never edited by hand. <Delete if the project commits them.> |
| End-to-end tests | `.maestro/` | Maestro flows, one file per user flow (`sign-in.yaml`). |

### Backend (`backend/`)

| Area | Path | What goes here |
| --- | --- | --- |
| Schemas | `<path>` | Data model definitions. |
| API logic | `<path>` | Controllers, routes and services; business logic shared by controllers goes into a service. |
| Input validation | `<path>` | Schemas that parse request bodies before any logic runs. |
| Configuration | `config/` | Values from environment variables, never hard-coded secrets. |
| Generated code | `<path>` | Written by tools; never edit. |

## Naming

- Component files PascalCase and named after their component (`OrderItem.tsx` exports `OrderItem`). Parts of a feature take the feature as prefix (`OrderItem`, `OrderSummary`).
- Other TypeScript files camelCase (`fetchOrders.ts`, `formatPrice.ts`); hooks start with `use`.
- Folders under `src/components`, `src/ui`, `src/hooks`, `src/state` and `src/data-access` are camelCase (`orderDetails`, `fetchSingleOrder`). Route files and folders in `src/app` are kebab-case (`order-history.tsx`) because they become deep link paths.
- Expo Router reserved names exactly (`_layout.tsx`, `+not-found.tsx`, `index.tsx`) and segment syntax only for routing intent (`[id]`, `[...rest]`, `(group)`).
- Platform files only for a large difference: `DatePicker.ios.tsx` and `DatePicker.android.tsx` export the same name and props; callers import `DatePicker`.
- Type and constant naming follows `AGENTS.md`, "Code conventions".

## Barrels and imports

- Every folder in `src/components`, `src/ui`, `src/data-access` and `src/state` has an `index.ts` that names what callers outside the folder use (`export { OrderList } from "./OrderList";`, `export type { IOrder } from "./validators";`), never `export *`. Callers import from the folder (`@/data-access/fetchOrders`, `@/ui`), not from files inside it.
- Import across folders with the `@/` alias; relative imports only inside one folder.
- Code that only build tooling may read (`app.config.ts`, config plugins, scripts) is never imported by app code.

## Placement rules

- Colocate first: code used by one component stays in its folder. Move it to `src/ui`, `src/hooks` or `src/shared` when a second feature needs it, or from the start when it is clearly generic (a formatter, an app-state hook, a button).
- Before writing a helper, search `src/shared` and `src/hooks`; a domain-free helper goes to `src/shared` from its first use, not as a private copy beside a component.
- A new API read or write is a new `src/data-access/<operation>/` folder, never a `fetch` written inside a component.
- A new stored value is a new wrapper in `src/storage` with a schema and a version.
- Tests live in a `__tests__` folder beside the code they test; never inside `src/app`.
